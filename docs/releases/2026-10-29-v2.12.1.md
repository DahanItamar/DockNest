# DockNest 2.12.1

Incremental backups get safer, and backups no longer copy SSH or GPG keys inside mounted folders.

## New

- **Restore an incremental backup with only the recovery kit.** From a plain copy of your storage folder, the kit finds the chain, checks it and rebuilds the files, including deleted and renamed folders.

## Better

- Update Center: when updates are rate limited, the message says which limit was reached and when you can update again.
- Update Center: an older failed update that the running version has already passed, for example after a manual upgrade, shows as Superseded.
- The Recovery guide uses plus and minus icons.

## Fixed

- Incremental backups: an increment that cannot be confirmed as part of its chain is not saved. The backup shows as failed, you get the Backup failed alert, and the next backup is full.
- Incremental backups: re-verifying a backup also checks the backups built on it, and alerts you if the chain is broken.
- Connections: clicking New connection while the list is still loading now opens the dialog.
- Install on server refuses to install Docker for a multi-container site when it cannot read which Docker version the server offers, and reports an apt removal conflict as a conflict.
- A command-line upgrade that cannot register with the host updater ends with the exact `--repair` command to run.

## Security

- **This changes what new backups contain.** `.ssh` and `.gnupg` folders inside a host folder mounted into a container, such as a home folder, are no longer copied. The job result and the readiness check name each folder left out.
- Restores and moves no longer keep setuid or setgid permissions or file capabilities on restored files.
