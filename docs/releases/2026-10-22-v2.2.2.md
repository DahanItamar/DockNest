# DockNest 2.2.2

Released 2026-10-22. [Full changelog](../../CHANGELOG.md).

## Summary

Fixes the host updater on systemd 259, where every in-app update stopped at release verification.

## What's new

Nothing new.

## Improved

- When the release verifier cannot start or crashes, the host updater writes its exit code and last error line to the journal (`journalctl -t docknest-updater`) instead of only `verify-unavailable`.

## Fixed

- In-app updates failed within a second with "Release verification failed (verify-unavailable)" on hosts with systemd 259 (for example Ubuntu 26.04). The service unit set `User=root` together with `NoNewPrivileges=yes`, which on systemd 259 removes `CAP_SETUID`, so the broker could not start the verifier account. The unit no longer sets `User=` (root is the default).

## Security

No security changes. The service keeps the same capability bounding set and hardening.

## Upgrade notes

The Update Center cannot install this release on an affected host, because the bug stops it before anything changes. Use one of these:

- `scripts/upgrade.sh --version v2.2.2`, then `sudo scripts/install-updater.sh --repair` from the checkout to install the fixed unit.
- Or delete the `User=root` line from `/etc/systemd/system/docknest-updater.service`, run `sudo systemctl daemon-reload` and `sudo systemctl restart docknest-updater.socket`, then use **Update to v2.2.2** in the Update Center. Run `sudo scripts/install-updater.sh --repair` afterwards so the installed unit matches the release.

Hosts where in-app updates already work need nothing beyond the normal update.
