# DockNest 2.4.0

Released 2026-10-23. [Full changelog](../../CHANGELOG.md).

## Summary

Problem reports without personal data. When something fails, administrators can open a pre-filled GitHub issue that carries only fixed, typed values, after reviewing exactly what will be shared. Upgrade if you want to report problems from DockNest; nothing else changes.

## What's new

- **Open GitHub on failures.** Failed and recovery-required jobs, storage and server connection tests, DockNest backup failures, failed updates (the result screen and failed rows in Recent updates) and unexpected app errors offer **Open GitHub**. A "Review what will be shared" dialog lists the exact title and values first; your browser then opens the issue form in a new tab. DockNest's server sends nothing and nothing is posted until you submit on GitHub. Administrators only; **Report a bug** in Settings > About stays available to every signed-in user.
- **Nothing private in a report.** Every value is checked against a fixed list or pattern and dropped if it does not match. Host names, addresses, URLs, paths, user names, emails, site and server names, ids, error text, logs and stack traces are never included. An environment section (coarse Docker, Compose, git, OS, kernel, architecture and free-disk values) is included by default and can be unticked. See [Problem reports](../security.md#problem-reports).
- **Update-failure reports.** The outcome, result, failed stage and phase, a timeline in relative seconds, the reason code, the schema change, the install mode and the updater version. Optionally, and off by default, the last error lines of that run, with addresses, paths, names and keys replaced by `[redacted]`, editable before sharing, and a **Copy excerpt** fallback when they do not fit in the link.
- **"This page stopped working".** An unexpected error in a page now shows a recovery screen with **Reload page** instead of a blank page. Its report carries only the page, the area and the error type (for example `TypeError`).

## Improved

- Settings > About: the button is labelled **Report a bug** and uses the same review dialog; on phones the dialog is a bottom sheet with full-width buttons.

## Fixed

None.

## Security

No security fixes. The report rules, the excerpt redaction and their limits are described in [Problem reports](../security.md#problem-reports). Security problems go through [SECURITY.md](../../SECURITY.md), not public issues.

## Upgrade notes

From 2.3.x, use **Update now** in the Update Center, or `scripts/upgrade.sh --version v2.4.0`. No metadata migration. The API changes are additive: storage and server connection test errors gain `errorClass` (and `check`) next to the unchanged message, the admin update status gains typed report fields, and `GET /api/updates/requests/:id` is new (administrators only).

## Known limits

- Engine and helper failures do not have reason codes yet, so job reports carry only the existing structured fields (job type, phase key, site kind, storage type, container count, helper outcome).
- The DockNest backup report carries the destination type and how it ended, not the phase (snapshot, encrypt, upload, verify): the phase is not recorded yet.
- The storage type in a job report is the currently selected destination, not one recorded with the job.
- The excerpt redaction is automatic and can miss private text; the dialog says so and the text is editable before sharing.
- GitHub applies the issue labels only once they exist in the repository.

## Validation

- **Tested:** unit tests (`npm run check`), including a canary test that plants host names, addresses, paths, emails, tokens, names, ids and error text into every report builder and the excerpt sources and checks that none reaches a link or the dialog; browser suites against mocked APIs (`npm run test:reports`, the Update Center, mobile, dashboard, servers, storage, DockNest backup and other suites), light and dark, 320 to 1440 px including 402 x 874.
- **Not covered:** a real failed backup, restore or update on Linux Docker; this release does not change backup, restore or update behaviour. Pending the private release validation on the release commit ([release validation](../release-validation.md)).
