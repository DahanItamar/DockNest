# DockNest 2.4.1

Released 2026-10-23. [Full changelog](../../CHANGELOG.md).

## Summary

A polish and clarity release. The pager keeps the same gap on every page, wide screens use their width, the Audit trail reads like a sentence, the collapsed sidebar rail is clean, every page has one filter, and the Update Center says which updater limit applied and when you can try again. Problem reports can now prefill "What happened?" without sharing anything private. Upgrade for a calmer, clearer interface; nothing about backups, restores or updates changes.

## What's new

- **A readable Audit trail.** Actions read as "Signed in", "Update requested", "Update refused", "Re-authenticated" or "Job superseded" (the raw code stays in **View details**). The actor is the person's display name, or System, Worker, Scheduler or Unknown user, never a raw id. Columns are proportional so nothing is cut off from 1280 px up, and **View details** is a frameless icon button like in Jobs.
- **"What happened?" in problem reports.** When a failure message is one of DockNest's own fixed messages, the issue form's "What happened?" field is prefilled from a built-in list (never from the server text). For any other message, an unticked **Include the error message** box lets you add it: redacted, at most 40 lines and 2 KiB, editable, shown in the review before GitHub opens, with a **Copy** fallback when it does not fit in the link. See [Problem reports](../security.md#problem-reports).

## Improved

- **Wide screens use their width.** From 1920 px the page keeps a 40 px edge (48 px from 2560 px) and the content grows to 2200 px at 2560 px and 3400 px at 3840 px, with the sidebar expanded or collapsed. Phone, tablet and 1440 px are unchanged.
- **Audit and Jobs fill the screen.** The row count follows the available height (never fewer than 10), with the pager in a stable place.
- **One filter per page, none in the header.** The header search box is gone. Servers, Sites & schedules, Backups, Jobs and Audit have a filter with a funnel icon ("Filter servers...") above the list and the record count on the right, with a proper singular ("1 record").
- **A clean collapsed rail.** Only a 44 px health pulse and a 44 px capacity ring, with no overlapping text and no frame at rest; the focus ring appears only for the keyboard. Details stay in the tooltip and popover.
- **Several storage destinations.** The sidebar readout and the rail popover name the destination they describe (the one selected for new backups); the Storage page shows four destinations per page, fitted to the screen, with long names wrapping inside their card and "Selected for new backups" on its own line.
- **Overview layout.** From 1024 px: two large cards (Sites with recovery points, Recovery points) and a third column with Active jobs above Average capture downtime, all edges aligned. The Recovery points card now opens on **Month** instead of Year.
- **Open GitHub shows the GitHub mark** on every problem-report button.
- **Counts read correctly.** A small shared helper writes "1 successful backup", "1 account", "1 minute", "1 recovery point" and similar everywhere in the interface.

## Fixed

- **The pager gap differed between pages.** On a full page the cards touched the pager, on a partial last page there was a gap. Card pages (Sites, Servers, Storage and every other card list) now keep the same 24 px gap on every page and every width, phones included (1024 to 3840 px on desktop), and the pager does not move.
- **"1 successful backups".** Retention and other counts used the plural for one.
- **Wrong message when the updater refused for rate limits.** It always said "wait a few minutes", even for the daily limit. The updater now says which limit applied: "The updater needs a minute between runs. Try again at 14:05." or "The updater allows 6 update runs a day. The next run is possible at 09:30." The limits themselves are unchanged. The API's own limit now says "Too many requests. Try again in N seconds."
- **Audit cells were truncated** (long ids, times cut with an ellipsis); see the Audit trail above.

## Security

No security fixes. The new prefill and its limits are described in [Problem reports](../security.md#problem-reports). Security problems go through [SECURITY.md](../../SECURITY.md), not public issues.

## Upgrade notes

From 2.4.0, use **Update now** in the Update Center, or `scripts/upgrade.sh --version v2.4.1`. No metadata migration. The API changes are additive: `GET /api/state` gains `actors` (display names, only for the accounts that appear in the audit rows it returns), a rate-limited update refusal gains `limit` and `retryAt`, and the progress limiter's 429 gains `retryAfter`. The exact limit and time come from the host updater: reinstall it once (`sudo scripts/install-updater.sh`) to get them; until then the Update Center shows a generic "limiting update runs" message with no time. The updater's protocol, limits and permissions are unchanged.

## Known limits

- The catalogue of fixed messages covers messages DockNest writes as literals; messages that include a name, path or address are not in it and need the opt-in box.
- The excerpt redaction is automatic and can miss private text such as a bare person's name; the dialog says so and the text is editable before sharing.
- With several storage destinations the sidebar readout shows only the one selected for new backups; each destination's own usage is not summed.

## Validation

- **Tested:** unit tests (`npm run check`, Python broker tests, catalogue and canary tests), and browser suites against mocked APIs: pagination (gap at five widths from 1024 to 3840), the new `npm run test:layout` (wide-screen frame, Overview grid, Audit, rail, filters, one to five storage destinations at 1440, 2560 and 402 px), Update Center, problem reports, mobile, rebrand, servers, dashboard and others, light and dark.
- **Not covered:** a real update, backup or restore on Linux Docker; this release does not change their behaviour. Pending the private release validation on the release commit ([release validation](../release-validation.md)).
