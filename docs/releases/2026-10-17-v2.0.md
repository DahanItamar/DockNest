# DockNest 2.0

Released 2026-10-17. All examples use mock data.

## Highlights

- **Large SQLite sites.** Databases over 1 GiB in WAL mode run `PRAGMA integrity_check` on a read snapshot before any service stops, so a long check no longer counts as downtime. The offline step records a SHA-256 that restore verification repeats. A timeout now reports a clear message instead of SQLite's bare `interrupted`.
- **Per-site check mode.** `sqliteIntegrityCheck` is `full` (default) or `off`. The dashboard keeps the saved value when a site is edited without it.
- **Unchanged database reuse.** A large rollback-journal database reuses its last passed offline check only when it is byte-identical: same inode, size, mtime and ctime, plus a fresh SHA-256 match. Restore never reuses.
- **Delivery modes in the dashboard.** Choose *Temporary copy, then upload* or *Stream directly to backup storage* per site; the review step shows the choice and any excluded backup scope.
- **Reliable direct streams.** `docker save` runs once into the job staging root and that exact file is streamed, because freshly committed images are not byte-stable across runs. Direct streams default to gzip level 1.
- **Live progress and real causes.** Jobs record transfer progress (bytes sent of total) and step diagnostics. Failures keep the underlying transport or storage reason with paths removed.
- **Sturdier connections.** SSH and storage sessions tolerate about 100 seconds of silence before giving up.

## Dashboard

- New Job details: status, started, duration, site paused and stage at a glance; "What happened" with the failure point; a progress bar with speed, time left and expected finish; a plain-language step timeline on a fixed grid. It refreshes every 5 seconds while a job runs.
- New Backup details: recovery point summary, contents, checks, storage and IDs.
- Audit, result and restore-plan views use the same readable layout with **View JSON** and **Copy**.
- Time-zone fields are a dropdown of common zones sorted by UTC offset.
- The capture activity chart opens on the last 7 days.

## Upgrade notes

- No database migration is required. Existing sites keep `sqliteIntegrityCheck` unset, which means `full`.
- Storage capacity reports real filesystem usage in `used`; DockNest's own package bytes are in `managedBytes`.
- Redis contracts additionally require `logfile ""` and `loglevel` notice or more verbose, and readable Docker logs, before any stop.
- Run `npm run check` and a real Linux Docker integration drill before relying on a new capture path in production.
