# DockNest 2.5.0

Released 2026-10-23. [Full changelog](../../CHANGELOG.md).

## Summary

A security and reliability release from a full audit of DockNest, plus branded error pages and automatic clean-up after updates. Every install should update.

## What's new

- Error pages in DockNest's own style: 404, 403, 401 and the "This page stopped working" screen, each with one clear button, plus a 503 page for reverse proxies that retries by itself.
- Leftover backup working folders on your servers are now cleaned up automatically after each backup (only folders of finished jobs).

## Improved

- Updates keep the previous release's image under a stable tag, so the rollback instructions always work.
- After a successful update, old DockNest images and build leftovers are removed automatically; other projects' images are never touched.
- Storage cards with two buttons use the full width.

## Fixed

- Since 2.1.0, successful backups skipped their clean-up: the unencrypted working copy stayed on the source server and retention never removed old recovery points. Both now work. On the first backup after updating, each site keeps exactly its retention number of recovery points (pinned ones are always kept).
- A source server with a wrong clock can no longer make retention delete the newest recovery point.

## Security

- Only administrators can add or change a site's file paths, staging or maintenance folder; protected system files (password and SSH key files, /proc, /sys, /dev) are never captured.
- Sign-in and API rate limits can no longer be bypassed by switching IPv6 addresses.
- Restore refuses archive link tricks that point outside the restore folder and archives larger than the free space.
- The maintenance page writer refuses planted links and special files.
- The host updater refuses unverified image installs and tampered status files; CI actions are pinned; no known dependency vulnerabilities.
- Restoring a recovery kit cancels old open invitations.

## Upgrade notes

From 2.4.x, use **Update now** in the Update Center, or `scripts/upgrade.sh --version v2.5.0`. No database migration. The image-retention fix applies from the update after this one (each update runs the script already installed); `docs/upgrading.md` explains the one-time `docker tag docknest:local docknest:previous` for 2.4.1 installs that want a rollback image now. A site whose saved paths include a protected system path stops backing up with a clear message until an administrator removes that path.

## Known limits

Unchanged from [2.4.0](2026-10-23-v2.4.0.md).

## Validation

CI on every pull request, including the Linux integration suite (real backup and restore). Pending the private release validation on the release commit.
