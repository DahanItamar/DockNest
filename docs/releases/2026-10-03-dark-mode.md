# Light and dark appearance

## M1 — Palette and controls

Light remains the default. A custom sun/moon control in the top bar and authentication headers switches between the existing light palette and deep navy dark surfaces, with blue/violet accents and semantic status colors. A local script applies the saved choice before React paints; tabs synchronize the same device preference. Appearance changes require no backend configuration or operational API writes.

The sun rays rotate on hover and the moon stars lift subtly. Reduced motion disables hover and state animation. Dark headers reuse the all-blue README logo with transparent 600/1200px WebP exports. Charts and legends follow the semantic palette, while data, periods, downloads, layouts and backup/restore controls retain their behavior. Maintenance visitor designs remain independent of the operator's app appearance.

## M2 — Verification and documentation

`npm run check` passed the build, 49 Node tests and Python helper verification. Browser checks covered both palettes across nine routes and sign-in/setup/enrollment, six responsive widths, equal cards, existing action requests and operator restrictions. Theme-specific checks covered text/control/status/focus contrast, keyboard switching, hover effects, reduced motion, persistence before React, cross-tab updates and blocked local storage.

CI includes the theme and shell checks. The logo guide and asset pack include both wordmark presentations. Reference roles and motion guidance are recorded in [reference roles](../agents/README.md). This presentation change does not establish additional recovery compatibility.
