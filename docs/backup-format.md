# Backup format v1

The payload file is DBM1 (4 ASCII bytes), a 12-byte random nonce, AES-256-GCM ciphertext, and the 16-byte authentication tag. The 16-byte header is authenticated as AAD. The encryption key is the 32-byte master key. SHA256 covers the entire encrypted file. Preserve the master key separately from the metadata database and payloads.

Plaintext is a gzip tar containing manifest.json, images.tar, and mount-I-J.tar files. The private manifest includes full Docker inspect configuration and snapshot image IDs; it contains secrets and must remain encrypted. Public database metadata excludes environment values and host source paths. Each mount archive preserves numerical UID/GID, modes, links, GNU tar ACLs and extended attributes. Committed snapshot images capture writable layers; images.tar includes both exact original image IDs/digests and committed snapshots. Mount archives capture attached data separately. Explicit Compose/config files and restore-guide.md are included.

The source stops only containers previously running, verifies clean zero exit codes, copies mounts without hard links, commits writable layers, restarts and checks health, disables maintenance, then saves images and compresses. A detached local watchdog terminates the helper process group at its deadline before recovery, starts previously running containers, and clears maintenance only after health succeeds. Review recovery.json after a disconnect. Staging and snapshot images are retained after failures; disk use requires operator review. Watchdog does not survive source-host reboot: arrange a boot recovery service before production use.

Single-container new-copy restore uses network none, fresh mount directories and no restart policy. Grouped restores on Docker 28+ create fresh internal bridge networks with isolated gateway mode, preserving original network membership and service DNS aliases. They publish no ports, disable external DNS forwarding and use a separate project identity. Identical shared mount sources remain shared; originally stopped services remain stopped. Captured images are loaded without registry pulls and running services are checked through Docker health. Console access is returned; production routing is a separate administrator action.

Static IP assignments, shared container network namespaces, overlapping mount paths, custom mappings, device files, escaping links and host privileges require reviewed adapters. Safe internal symlinks and hardlinks are preserved. Replacement has additional safety-backup and rollback requirements and remains blocked. Actual isolated Linux backup/restore and recovery evidence is recorded in [acceptance](acceptance.md).

Offline recovery must first authenticate the whole ciphertext to a private temporary file. Never pipe unauthenticated decrypted bytes into an extractor. Check paths, reject absolute/traversal names and links escaping destination, inspect configuration, load images, recreate isolated networks and new mount destinations, and create containers without privileged access or host namespaces. Original inspect settings contain credentials and must be handled as secrets. Do not reuse production ports, restart policies or external connections. A checksum verifies transport integrity; it does not prove a working restored application.

Shutdown profiles: generic requires cleanShutdownConfirmed; PostgreSQL/MySQL require matching image identification and clean database shutdown log markers plus zero container exit codes. Manifest contains evidence booleans, never raw logs.

Current capture blockers: Compose sites without explicit project files and dependency confirmation; privileged/device-backed containers; unreviewed tmpfs and system mounts; shared mounts with outside running containers; no explicit exclusiveSourcesConfirmed assertion; non-root SSH; graceful exit code other than zero. Explicitly declared `/tmp`, `/run/mysqld` and `/var/run/mysqld` RAM folders are recreated empty with original size/options and permissions. Their contents disappear when the source stops and are not called persistent backup data. Unknown destinations/options remain blocked. External writers cannot be inferred from Docker alone: the administrator must confirm exclusive ownership. Database-specific shutdown proof beyond the configured clean-exit profile requires integration validation.

Full ZIP exports authenticate GCM and the stored ciphertext checksum into a private temporary gzip tar before emitting any plaintext to the browser. The ZIP is then streamed to the browser as it is built, so only the decrypted payload needs temporary space: the backup's size plus a 2 GiB reserve, watched while it is written (the export stops cleanly if free space falls below 1 GiB). A failure after the first byte ends the download as failed, never as a silently short file. A single export is allowed per API instance, with mode-0600 files, cancellation cleanup and startup removal of interrupted export directories. ZIP64 supports large archives. `recovery-originals/` retains all original image/mount/config tar archives and the private manifest; `site-files/` and `configuration/` provide convenient browsing copies. Hardlink contents are copied; symlinks are described without creating links. Original tar archives preserve full Linux metadata for recovery. ZIP downloads are decrypted, may be larger, and cannot be resumed with byte ranges. The ordinary encrypted download still supports ranges.

Maintenance HTML distribution over SSH is implemented; proxy maintenance uses an administrator-reviewed Nginx integration template. Distribution does not report readiness automatically. A readiness marker alone does not prove routing: public 503 and internal health probes are required. Configure TLS and JSON API responses independently. The public probe requires HTTP 503 with the deployed dbm-maintenance-v1 marker. After internal health succeeds, disabling maintenance also requires a public HTTP 200 response without that marker; failure reinstates maintenance.

Retention removes only ordinary verified backups beyond the configured count after a new successful capture, and respects active download and restore records. Pinned backups are additional to the count. Interrupted jobs enter recovery_required and prevent further work on their server. Resolve source health and watchdog state before changing job status. A single expiring SQLite worker lease (not a lock file) prevents concurrent workers; after an unclean death the next worker takes it over once it is 60 seconds stale and marks interrupted jobs recovery_required. Central restart does not silently assume remote recovery succeeded.
